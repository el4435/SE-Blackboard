# 7. Threats to Validity

**Internal Validity.** Our experiments use a single LLM (Claude Sonnet 4.5) with temperature 0, ensuring deterministic generation within each configuration. However, results may differ with other models [Brown et al., 2020], as LLMs vary in their sensitivity to prompt format, context length, and structured output generation. The use of temperature 0 eliminates sampling variance but may not represent typical production usage where non-zero temperatures are common. Additionally, the sequential pipeline topology introduces an ordering effect: if the Planner produces a poor analysis, all downstream agents are affected regardless of communication architecture.

**External Validity.** Our evaluation uses 50 issues sampled from SWE-bench Lite, which focuses on well-maintained Python repositories. Results may not generalize to other programming languages, less well-structured codebases, or different types of SE tasks (e.g., feature development, refactoring). The sample of 50 issues, while covering 8 repositories, is small relative to the 300-issue full SWE-bench Lite benchmark. Django issues are overrepresented (22/50), and since BB's advantage concentrates in Django, the effect may be partially confounded with repository-specific factors.

**Construct Validity.** The Information Fidelity Score uses rule-based entity extraction (regular expressions for function names, class names, file paths, etc.), which may miss semantically equivalent but lexically different references. For example, if the issue mentions `FilePathField` and the Coder's output discusses `the file path field class`, IFS would not count this as preservation despite semantic equivalence. Conversely, incidental mentions of an entity (e.g., in boilerplate text) are counted as preservation even if the agent does not meaningfully use the information. Future work should explore embedding-based or semantic matching approaches for more nuanced fidelity measurement.

Additionally, resolve rate as the sole primary metric may understate the actual impact of communication architecture. Our intermediate metrics (IFS, correct file targeting rate) reveal that BB achieves significant advantages upstream---83% correct file targeting versus 55% for MP---that are attenuated by a downstream bottleneck shared across all configurations. This suggests that resolve rate alone provides an incomplete picture of architectural effectiveness, and that multi-stage evaluation pipelines are needed for fair comparison of communication architectures in multi-agent SE systems.

**Statistical Validity.** The sample size of 50 issues provides limited statistical power for detecting differences in resolve rate. With only 4 discordant pairs between MP and BB, McNemar's test is severely underpowered. The marginally significant IFS result ($p=0.058$) should be interpreted cautiously: while it approaches conventional significance, it does not meet the $\alpha=0.05$ threshold, and we did not apply corrections for multiple comparisons. We present these results as suggestive evidence warranting larger-scale validation rather than definitive proof of effect.
