# 2. Related Work

## 2.1 Multi-Agent Systems for Software Engineering

Recent work has produced numerous multi-agent SE systems spanning different architectures and interaction paradigms. These multi-agent systems build upon the code generation capabilities of foundation models such as Codex [Chen et al., 2021] and Code Llama [Roziere et al., 2023], which demonstrated that LLMs pretrained or fine-tuned on code can generate functionally correct programs from natural language descriptions. Role-based frameworks like MetaGPT [Hong et al., 2024], ChatDev [Qian et al., 2024], and AutoGen [Wu et al., 2023] assign specialized roles (planner, coder, reviewer) to agents and coordinate them through structured workflows or dialogue. Tool-augmented approaches such as SWE-Agent [Yang et al., 2024] and AutoCodeRover [Zhang et al., 2024] equip agents with repository navigation tools, achieving competitive results without explicit multi-agent coordination. For automated bug fixing specifically, AgentCoder [Huang et al., 2024] and CodeR [Chen et al., 2024] employ multi-agent pipelines with iterative test feedback, while Agentless [Xia et al., 2024] demonstrates that structured prompting can match agent-based approaches, suggesting that the interaction pattern may matter as much as agent autonomy.

A common thread across these systems is their reliance on message-passing or simple role-chaining for inter-agent communication. While some systems like MetaGPT incorporate shared artifacts (e.g., design documents), the communication architecture itself is not treated as an independent variable. Our work addresses this gap by isolating the effect of communication architecture on task outcomes.

## 2.2 Communication Architectures for LLM Agents

He et al. [2025] provide a comprehensive survey of LLM-based multi-agent systems for software engineering, categorizing systems along dimensions including agent roles, interaction patterns, and communication mechanisms. Their taxonomy identifies several communication modes---including direct messaging, shared memory, and blackboard systems---but notes that most existing SE systems use simple sequential or conversational communication.

Zhang et al. [2025] systematically analyze why multi-agent LLM systems fail, identifying *knowledge drift* as a primary failure mode. In knowledge drift, information is progressively distorted as it passes through multiple agents, with each agent's paraphrasing introducing potential inaccuracies. Their analysis demonstrates that longer agent chains exhibit higher drift rates, suggesting that architectural interventions at the communication level could be more effective than improvements to individual agent capabilities.

Beyond inter-agent communication, recent work has advanced the reasoning capabilities of individual agents within multi-agent systems. Chain-of-Thought prompting [Wei et al., 2022] enables step-by-step reasoning, while ReAct [Yao et al., 2023] synergizes reasoning with tool use to ground agent actions in environmental feedback. Reflexion [Shinn et al., 2023] introduces verbal reinforcement learning, allowing agents to iteratively improve through self-reflection on past failures. [Park et al., 2023] demonstrate that generative agents with memory and reflection capabilities can exhibit realistic collaborative behaviors, providing a foundation for more sophisticated multi-agent coordination.

RTADev [Fang et al., 2025] addresses the communication quality problem through intention alignment: after each agent produces output, a verification step checks whether the output faithfully represents the original intent. While effective at detecting drift, this approach is *reactive*---it identifies information loss post-hoc rather than preventing it architecturally. In contrast, the Blackboard architecture we adopt is *proactive*, ensuring that all agents maintain access to source information regardless of intermediate processing.

## 2.3 Blackboard Architecture

The Blackboard architecture, originally proposed by Nii [1986], provides a problem-solving framework in which multiple knowledge sources (KSs) collaborate through a shared workspace called the blackboard. Each KS monitors the blackboard for relevant changes, contributes its expertise when applicable, and writes results back to the shared workspace. A control component determines the order of KS activation. This architecture was historically applied to speech understanding in the HEARSAY-II system [Erman et al., 1980], image interpretation, and planning systems.

The resurgence of interest in the Blackboard pattern for LLM-based systems is driven by its natural fit for multi-agent coordination. Wang et al. [2025] introduce LbMAS, a Blackboard-based framework for LLM agent reasoning tasks. Their work demonstrates that shared-state communication significantly reduces information loss compared to message-passing, particularly in tasks requiring the synthesis of information from multiple sources. Critically, they show that the Blackboard's advantage scales with task complexity and agent chain length.

Salemi et al. [2025] apply the Blackboard architecture to data science tasks, where multiple agents collaborate on data analysis through a shared workspace containing datasets, intermediate results, and analysis plans. Their results show improved coherence and reduced redundant computation when agents can directly observe each other's outputs rather than receiving summarized reports.

Our work extends this line of research by applying the Blackboard architecture to software engineering for the first time. SE tasks present unique challenges for shared-state communication: the state must represent heterogeneous artifacts (issue descriptions, code context, patches, reviews, test results) with clear ownership semantics, and the precision requirements for code-related information are substantially higher than for natural language reasoning tasks.
